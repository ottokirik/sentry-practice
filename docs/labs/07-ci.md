# Лаба 07. CI: токен уезжает с ноутбука

**~50 минут**

## Цель

Перенести сборку и заливку карт в GitHub Actions, чтобы auth-токен жил в
секретах, а не в файле у тебя на диске. Заодно — два живых стенда и привязка
релиза к коммитам.

## Теория на пять строк

Пока токен лежит в `excalidraw-app/.env.sentry-build-plugin`, у тебя дома, всё
держится на честном слове: файл можно случайно закоммитить, скопировать в
чат, забыть на общей машине. В нормальном процессе прод-сборку делает только
CI, и токен есть только у CI.

Второй смысл — воспроизводимость. У CI всегда чистое дерево, поэтому релиз,
собранный из хеша коммита, действительно соответствует коду (помнишь
предупреждение из лабы 03).

## Задание

### 1. Заведи репозиторий и залей код

```bash
gh repo create sentry-practice --public --source=. --remote=origin --push
```

### 2. Положи токен в секреты

```bash
gh secret set SENTRY_AUTH_TOKEN
```

Команда спросит значение — вставь тот же токен, что в лабе 04.

Проверь: `gh secret list`.

### 3. Разберись с путями — тут ловушка

GitHub Pages для репозитория отдаёт сайт не с корня домена, а с
`https://<логин>.github.io/sentry-practice/`. Сборка Vite по умолчанию
рассчитана на корень и по такому адресу развалится: все ассеты уйдут в 404.

Напрашивается `base: "/sentry-practice/"`. **Так делать не надо.** Excalidraw
подставляет путь ассета в адрес своего CDN шрифтов, срезая ведущий слэш, и
получается вот что:

```
https://excalidraw.nyc3.cdn.digitaloceanspaces.com/oss/sentry-practice/fonts/... → 403
```

Рабочий вариант — **относительный** `base`. Тогда ассеты адресуются от текущего
каталога и одна и та же сборка работает на любой глубине вложенности. Кстати,
в `excalidraw-app/package.json` не зря стоит `"homepage": "."` — авторы имели в
виду ровно это, просто Vite, в отличие от CRA, это поле не читает.

Добавь `base` в `excalidraw-app/vite.config.mts`.

### 4. Напиши workflow

Требования:

- staging собирается при пуше в `main`, production — при пуше тега `v*`;
- релиз для прода берётся из имени тега, для staging — из хеша коммита;
- токен приходит из секретов;
- **перед деплоем пайплайн проверяет, что в сборке нет ни одного `.map`** —
  это страховка от того, что заливка отвалится, а мы не заметим;
- prod кладётся в корень Pages, staging — в подкаталог `staging/`,
  и они не затирают друг друга.

Последнее исключает готовый `actions/deploy-pages`: он публикует артефакт
целиком и при выкладке прода снёс бы staging. Поэтому деплой — своими руками
через `git`, в ветку `gh-pages`.

### 5. Привяжи коммиты к релизу

Добавь в `sentryVitePlugin` секцию `release` с `setCommits`. Тогда на странице
релиза появится список коммитов, а в событиях — **suspect commits**,
подозреваемый коммит с автором.

Для этого нужны две вещи: `fetch-depth: 0` в checkout (иначе истории нет) и
установленная интеграция Sentry с GitHub — **Settings → Integrations → GitHub**.
Без интеграции коммиты подтянутся, но останутся без ссылок на GitHub.

<details>
<summary>Эталон</summary>

`excalidraw-app/vite.config.mts`, в начало возвращаемого объекта:

```ts
    // Относительные пути: одна сборка работает и в корне, и в подкаталоге
    // Pages. Абсолютный base ломает адреса CDN-шрифтов Excalidraw.
    base: "./",
```

в `sentryVitePlugin`:

```ts
        release: {
          name: process.env.VITE_APP_RELEASE,
          setCommits: {
            auto: true,
            ignoreMissing: true,
            ignoreEmpty: true,
          },
        },
```

`.github/workflows/deploy.yml`:

```yaml
name: deploy

on:
  push:
    branches: [main]
    tags: ["v*"]

permissions:
  contents: write

jobs:
  deploy:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
        with:
          fetch-depth: 0 # нужна история для setCommits

      - uses: actions/setup-node@v4
        with:
          node-version: 22
          cache: yarn

      - run: yarn install --frozen-lockfile

      - name: Определить стенд
        id: stand
        run: |
          if [[ "$GITHUB_REF" == refs/tags/* ]]; then
            echo "mode=production"                             >> "$GITHUB_OUTPUT"
            echo "release=excalidraw-lab@$GITHUB_REF_NAME"     >> "$GITHUB_OUTPUT"
          else
            echo "mode=staging"                                >> "$GITHUB_OUTPUT"
            echo "release=excalidraw-lab@$(git rev-parse --short HEAD)" >> "$GITHUB_OUTPUT"
          fi

      - name: Сборка и заливка карт
        env:
          SENTRY_AUTH_TOKEN: ${{ secrets.SENTRY_AUTH_TOKEN }}
          VITE_APP_RELEASE: ${{ steps.stand.outputs.release }}
        run: |
          yarn workspace excalidraw-app exec -- \
            vite build --mode ${{ steps.stand.outputs.mode }}

      - name: Проверить, что карты не уезжают наружу
        run: |
          count=$(find excalidraw-app/build -name '*.map' | wc -l)
          echo "карт в сборке: $count"
          test "$count" -eq 0

      - name: Деплой на Pages
        env:
          GH_TOKEN: ${{ secrets.GITHUB_TOKEN }}
          MODE: ${{ steps.stand.outputs.mode }}
          RELEASE: ${{ steps.stand.outputs.release }}
        run: |
          tmp=$(mktemp -d)
          repo="https://x-access-token:$GH_TOKEN@github.com/$GITHUB_REPOSITORY.git"

          # ветка gh-pages может ещё не существовать
          if ! git clone --branch gh-pages --depth 1 "$repo" "$tmp" 2>/dev/null; then
            git clone --depth 1 "$repo" "$tmp"
            git -C "$tmp" checkout --orphan gh-pages
            git -C "$tmp" rm -rf . >/dev/null
          fi

          if [ "$MODE" = "production" ]; then
            # чистим корень, но бережём соседний стенд
            find "$tmp" -mindepth 1 -maxdepth 1 \
              ! -name .git ! -name staging -exec rm -rf {} +
            cp -r excalidraw-app/build/. "$tmp/"
          else
            rm -rf "$tmp/staging"
            mkdir -p "$tmp/staging"
            cp -r excalidraw-app/build/. "$tmp/staging/"
          fi

          touch "$tmp/.nojekyll"

          cd "$tmp"
          git config user.name "github-actions[bot]"
          git config user.email "github-actions[bot]@users.noreply.github.com"
          git add -A
          git commit -m "deploy $MODE $RELEASE" || echo "изменений нет"
          git push origin gh-pages
```

</details>

### 6. Включи Pages

После первого успешного прогона появится ветка `gh-pages`. Тогда:

**Settings → Pages → Source: Deploy from a branch → `gh-pages` / `(root)`**

### 7. Убери токен с ноутбука

Ради этого всё и затевалось:

```bash
rm excalidraw-app/.env.sentry-build-plugin
```

Локальная прод-сборка теперь честно скажет `No auth token provided` — и это
правильно. Прод собирает CI.

## Проверка

```bash
git push origin main
```

Дождись зелёного прогона, открой `https://<логин>.github.io/sentry-practice/staging/`,
нажми детонатор 1. Событие должно прийти с окружением `staging`.

Теперь прод:

```bash
git tag v0.1.0 && git push origin v0.1.0
```

Открой `https://<логин>.github.io/sentry-practice/`, нажми детонатор 1.
Окружение — `production`, релиз — `excalidraw-lab@v0.1.0`, стектрейс читаемый.

Проверь, что стенды не затёрли друг друга: staging по своему адресу всё ещё
открывается.

И главное:

```bash
curl -s -o /dev/null -w "%{http_code}\n" \
  https://<логин>.github.io/sentry-practice/sw.js.map
```

`404`. Карт снаружи нет, а стектрейсы читаемые.

## Что должно сломаться, если сделать неправильно

| Симптом | Причина |
|---|---|
| Белая страница, в консоли 404 на ассеты | `base` не относительный |
| Шрифты 403 с адреса CDN | Поставил абсолютный `base: "/sentry-practice/"` — см. пункт 3 |
| Шаг проверки карт валит пайплайн | И хорошо: значит заливка не прошла. Смотри лог шага сборки |
| `Permission denied` при push в gh-pages | Нет `permissions: contents: write` |
| Прод снёс staging | В ветке деплоя пропущен `! -name staging` |
| Suspect commits пустые | Нет `fetch-depth: 0` или не установлена интеграция с GitHub |
| 404 на самом сайте | Pages не включены, либо выбрана не та ветка |

## Итог

- [ ] Репозиторий на GitHub, токен в секретах
- [ ] Workflow собирает staging из `main` и prod из тега
- [ ] Пайплайн падает, если в сборке остались карты
- [ ] Оба стенда живут на Pages и не затирают друг друга
- [ ] Токена на ноутбуке больше нет
