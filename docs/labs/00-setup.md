# Лаба 00. Подготовка: аккаунт, проект, DSN

**~15 минут**

## Цель

Получить рабочий проект в Sentry и убрать из репозитория чужую конфигурацию,
чтобы дальше писать свою с чистого листа.

## Теория на пять строк

Иерархия в Sentry: **организация** → **проект** → **события**. Проект — это
обычно одно приложение (фронтенд и бэкенд чаще разносят по разным проектам).
У каждого проекта есть **DSN** — строка вида
`https://<ключ>@<org>.ingest.sentry.io/<id>`, по которой SDK знает, куда слать.

**DSN — не секрет.** Он попадает в бандл и виден любому, кто откроет devtools.
Так задумано: DSN даёт право только *писать* события в проект, не читать.
Секрет в этом практикуме будет ровно один — auth-токен из лабы 04.

## Задание

### 1. Заведи проект в Sentry

1. Зайди на [sentry.io](https://sentry.io). Если аккаунта нет — заведи,
   бесплатного тарифа хватит с запасом.
2. Создай проект: **Projects → Create Project**.
   - платформа — **React**
   - имя — например `excalidraw-lab`
3. Sentry покажет страницу онбординга с готовым сниппетом. **Не копируй его
   целиком** — там будет лишнее. Забери оттуда только DSN.

Если страницу онбординга уже закрыл, DSN всегда лежит здесь:
**Settings → Projects → `excalidraw-lab` → Client Keys (DSN)**.

### 2. Осмотрись

Загляни в два места — они понадобятся во всех следующих лабах:

- **Issues** — сюда будут прилетать ошибки. Сейчас пусто.
- **Settings → Projects → `excalidraw-lab` → Client Keys (DSN)** — здесь DSN.

Обрати внимание: списка окружений нигде нет и создать их заранее нельзя.
Окружения появятся сами, когда придёт первое событие с полем `environment`.
Это лаба 02.

### 3. Убери чужую конфигурацию

В Excalidraw Sentry уже подключён. Настроен он под них, а не под тебя:
DSN зашит в код, окружение вычисляется по имени хоста в рантайме, заливки
source maps нет вовсе. Дальше ты напишешь свою конфигурацию, поэтому текущую
надо снять.

1. Удали файл `excalidraw-app/sentry.ts`.
2. Убери его импорт из `excalidraw-app/index.tsx`.
3. **Не трогай** `excalidraw-app/components/TopErrorBoundary.tsx` — он тоже
   зовёт Sentry, но им займёмся в лабе 01.

Оригинал сохранён в `docs/upstream/sentry.original.ts` — в лабе 08 будем
сравнивать с ним свой результат. Восстанавливать его из git не понадобится.

<details>
<summary>Эталон</summary>

```bash
rm excalidraw-app/sentry.ts
```

В `excalidraw-app/index.tsx` удали строку:

```ts
import "../excalidraw-app/sentry";
```

Должно остаться так:

```tsx
import { StrictMode } from "react";
import { createRoot } from "react-dom/client";
import { registerSW } from "virtual:pwa-register";

import ExcalidrawApp from "./App";
```

</details>

## Проверка

```bash
yarn test:typecheck
```

Ожидаемо: `Done in ~6s`, без ошибок.

Теперь запусти приложение и убедись, что оно живо:

```bash
yarn start
```

Открой `http://localhost:3001`, нажми **💣 Sentry lab** в левом нижнем углу и
жми детонатор **1. Синхронный throw**. В консоли браузера появится
`SENTRY LAB: synchronous throw in a click handler`.

В Sentry при этом **ничего не появится** — и это правильный результат лабы.
SDK больше не инициализирован, слать events некому.

## Что должно сломаться, если сделать неправильно

| Симптом | Причина |
|---|---|
| `Failed to resolve import "../excalidraw-app/sentry"` | Файл удалил, импорт оставил |
| Ошибки всё ещё приходят в Sentry | Удалил не тот файл; проверь, что `excalidraw-app/sentry.ts` действительно нет |
| Приложение падает при детонаторе 6 | Это ожидаемо и не связано с Sentry — см. «Известная особенность» в [docs/README.md](../README.md) |
