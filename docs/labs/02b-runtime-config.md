# Лаба 02b. Одна сборка — много стендов

**~30 минут**

## Цель

Собрать **один** артефакт и раскатать его без изменений на несколько стендов
так, чтобы каждый стенд сам сообщал Sentry своё окружение.

## Теория

### Модель

Артефакт собирается один раз, проходит тесты, кладётся в хранилище
артефактов и дальше не меняется. На staging, на тестовый стенд и на прод
уезжает побайтово одно и то же. Всё, чем стенды отличаются, стенд сообщает
сам при запуске.

Для Sentry это разделение выглядит так:

| Что | Где живёт | Почему |
|---|---|---|
| `release` | в сборке | Это идентификатор артефакта. Одинаковый релиз на всех стендах — полезный сигнал: «падает только на одном стенде» почти всегда означает проблему конфигурации, а не кода |
| source maps | заливаются один раз при сборке | Debug ID вычисляется из содержимого, так что одна заливка работает для всех стендов |
| DSN | в сборке | Проект Sentry один на все стенды |
| `environment`, `stand`, сэмплирование | **на стенде** | Это и есть то, чем стенды отличаются |

### Сложность: окружение нужно знать до старта

`Sentry.init` должен выполниться раньше кода приложения, иначе ошибки старта
пройдут мимо. Если стенд узнаёт свою конфигурацию асинхронным запросом, к
моменту `init` ответа ещё нет.

Решение — отдавать то, что нужно знать до старта, **синхронным скриптом**:

```html
<script src="./config.js"></script>
```

Обычный `<script>` без `async`, `defer` и `type="module"` выполняется прямо
во время разбора HTML. Бандл Vite подключается как `type="module"`, а такие
скрипты откладываются до конца разбора. Значит, `config.js` гарантированно
отработает раньше.

Файл `config.js` в сборку не входит. Его пишет стенд при запуске — ровно там
же, где у контейнера уже формируется остальная конфигурация.

### Окружение — класс, стенд — тег

Если стендов много, не стоит заводить по окружению на каждый. Правила алертов,
фильтры и выпадающий список в Sentry рассчитаны на несколько значений: алерт
«ошибки на проде» должен задаваться одним условием, а не списком из
шестнадцати стендов. Поэтому:

- `environment` — класс стенда: `staging`, `production`
- тег `stand` — конкретный стенд: `staging-01`

## Что уже есть в репозитории

- `deploy/stands/*.json` — конфигурации трёх стендов. Изображают ответ
  внутреннего сервиса конфигурации
- `deploy/render-config.sh` — делает то же, что entrypoint контейнера: `curl`
  забирает конфигурацию, `jq` раскладывает её на статические файлы рядом со
  сборкой. Пишет `config/app.json` для остального приложения и `config.js`
  для того, что нужно до старта. Построчный разбор команды `jq` — в
  [docs/notes/render-config-jq.md](../notes/render-config-jq.md)
- `deploy/serve-stand.sh <стенд> <порт>` — копирует сборку в `.stands/<стенд>`,
  запускает `render-config.sh` и раздаёт результат
- тип `AppRuntimeConfig` и `window.__APP_CONFIG__` объявлены в
  `excalidraw-app/global.d.ts`
- панель-детонатор показывает `stand` и `env` из конфигурации стенда

Скриптам нужен `jq`:

```bash
mise use -g jq
```

Посмотри, что пишет скрипт для одного стенда:

```bash
deploy/render-config.sh "file://$PWD/deploy/stands/staging-01.json" /tmp/stand-demo
cat /tmp/stand-demo/config.js
```

## Задание

### 1. Оставь одну сборку

В `excalidraw-app/package.json` замени `build:staging` и `build:production`
одним скриптом `build:artifact`. Режим указывать не нужно: `vite build` по
умолчанию собирает в режиме `production` и берёт DSN из `.env.production`.

Файл `.env.staging` удали. Staging-сборки больше не существует.

### 2. Подключи `config.js`

В `excalidraw-app/index.html` добавь `<script src="./config.js"></script>`
внутрь `<head>`, перед `</head>`.

Путь должен быть **относительным** (`./config.js`): в лабе 07 стенды будут
жить в подкаталогах.

При сборке Vite выведет предупреждение:

```
<script src="./config.js"> in "/index.html" can't be bundled without type="module" attribute
```

Это ожидаемо и правильно: файл не должен попасть в бандл, его пишет стенд.
**Не добавляй `type="module"`**, чтобы убрать предупреждение: тогда Vite
попытается собрать несуществующий файл, а скрипт перестанет быть синхронным.

### 3. Возьми окружение из конфигурации стенда

В `excalidraw-app/sentry.ts`:

- `environment` — из `window.__APP_CONFIG__`
- тег `stand` — тоже оттуда. Проставь его сразу при инициализации, чтобы он
  был и у ошибок старта
- `enabled` по `MODE` оставь как есть

И реши, что делать, если конфигурации нет. Стенд, на котором `config.js`
не записался, — это сломанная раскатка. Промолчать или сообщить?

<details>
<summary>Эталон</summary>

`excalidraw-app/package.json`:

```json
"build:artifact": "vite build",
```

`excalidraw-app/index.html`, перед `</head>`:

```html
    <!-- Конфигурация стенда: пишется при раскатке, в сборку не входит.
         Обычный синхронный скрипт, поэтому выполнится раньше бандла. -->
    <script src="./config.js"></script>
  </head>
```

`excalidraw-app/sentry.ts`:

```ts
import * as Sentry from "@sentry/react";

// Окружение — свойство стенда, а не сборки. config.js пишется при раскатке
// и подключён в index.html раньше бандла, поэтому здесь он уже есть.
const runtimeConfig = window.__APP_CONFIG__;

Sentry.init({
  dsn: import.meta.env.VITE_SENTRY_DSN,
  // Нет конфигурации — не молчим, а честно помечаем: раскатка сломана.
  environment: runtimeConfig?.environment ?? "unconfigured",
  // MODE по-прежнему отличает дев-сервер от сборки, но не стенды.
  enabled: import.meta.env.MODE !== "development",
  initialScope: {
    tags: { stand: runtimeConfig?.stand ?? "unconfigured" },
  },
});
```

</details>

## Проверка

### Одна сборка, два стенда

```bash
yarn workspace excalidraw-app build:artifact
```

Дальше в двух терминалах:

```bash
deploy/serve-stand.sh staging-01 5091
```

```bash
deploy/serve-stand.sh production-01 5092
```

Открой оба адреса и разверни панель. На обоих будет `mode: production` — это
сборка. А строка ниже разная: `stand: staging-01 · env: staging` и
`stand: production-01 · env: production` — это стенды.

Убедись, что артефакт действительно один:

```bash
diff -rq .stands/staging-01 .stands/production-01
```

Стенды отличаются ровно двумя файлами — `config.js` и `config/app.json`.
Весь остальной код, до последнего байта, одинаковый.

Нажми детонатор 1 на обоих стендах. В Sentry у событий будут разные
`environment` и тег `stand`. Попробуй поиск в Issues: `stand:staging-01`.

### Сломанная раскатка

Раздай сборку, не записав конфигурацию:

```bash
npx http-server excalidraw-app/build -p 5093 -c-1 --silent
```

Приложение работает, в консоли 404 на `config.js`, в панели
`stand: (нет config.js)`. Нажми детонатор 1 — событие придёт с окружением
`unconfigured`. В рабочем проекте это стоит повесить на алерт.

### Дев-сервер

`yarn start` — в консоли будет 404 на `config.js`. Это нормально:
конфигурации стенда в разработке нет, а Sentry там выключен.

## Как это перенести на рабочий проект

Если entrypoint контейнера уже раскладывает конфигурацию стенда по статическим
файлам, изменение сводится к одной дополнительной строке `jq` — посмотри
последнюю команду в `deploy/render-config.sh`. Ещё три вещи:

- **`config.js` отдавай с `Cache-Control: no-cache`.** Иначе после
  перенастройки стенда браузер ещё какое-то время будет брать старую версию
- **В `config.js` нет места секретам.** Он публичный, как и JSON-файлы рядом
- **Если синхронный скрипт невозможен** и конфигурация приходит только
  запросом, остаётся другой путь: инициализировать Sentry сразу с
  `environment: "pending"` и проставлять настоящее окружение в `beforeSend`,
  когда ответ придёт. Это работает, но только для ошибок: `beforeSend`
  обрабатывает события ошибок, а остальное, что отправляет SDK, сохраняет
  окружение из `init`. Трейсы пришлось бы исправлять отдельно в
  `beforeSendTransaction`. Поэтому синхронный конфиг лучше

## Что должно сломаться, если сделать неправильно

| Симптом | Причина |
|---|---|
| Все события с `unconfigured`, хотя `config.js` отдаётся | Тег стоит после бандла или с `defer`/`async`/`type="module"` |
| На стенде в подкаталоге загрузился чужой `config.js` | Путь абсолютный (`/config.js`), а не `./config.js` |
| `Property '__APP_CONFIG__' does not exist` | Тип объявлен вне `declare global` — в `global.d.ts` он уже есть, не дублируй |
| Сборка падает с `Could not resolve "./config.js" from "index.html"` | Добавил `type="module"` к тегу |
| `diff -rq` показывает различия в `assets/` | Стенды раскатаны из разных сборок: пересобери и перезапусти оба |
| После пересборки в панели старые значения | Сервис-воркер Excalidraw отдал закешированную сборку. Обнови страницу ещё раз или удали его: DevTools → Application → Service Workers → Unregister |
| `нужен jq` | `mise use -g jq` |
