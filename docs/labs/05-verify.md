# Лаба 05. Проверка: читаемо в Sentry, закрыто снаружи

**~20 минут**

## Цель

Убедиться командами, а не на глаз, что оба требования выполнены
одновременно. И найти утечку, которую наивная проверка пропускает.

## Задание

### 1. Читаемый стектрейс

Раскатай сборку из лабы 04 на два стенда (важно: именно её — Debug ID должны
совпадать с тем, что залито). `serve-stand.sh` копирует сборку при запуске,
так что стенды, поднятые до пересборки, надо перезапустить:

```bash
deploy/serve-stand.sh production-01 5092
```

```bash
deploy/serve-stand.sh staging-01 5091
```

Открой `http://localhost:5092`, жми детонатор **1**, открой событие в Sentry.

Теперь вместо `at fire (index-rZz89yEX.js:2640:2592)` должно быть примерно так:

```
at fire (excalidraw-app/debug/DebugPanel.tsx:71:15)
```

плюс подсвеченный кусок исходного кода вокруг падения. Проверь заодно
детонатор **4** — он падает в отдельном ленивом чанке, и это отдельный файл со
своей картой.

Теперь то же на `http://localhost:5091`. Стектрейс со staging-стенда тоже
читаемый, хотя для него ничего отдельно не заливали. Карты привязаны к
содержимому файлов через Debug ID, а содержимое на всех стендах одно. Одна
заливка при сборке — и расшифровка работает на всех шестнадцати стендах
сразу.

### 2. Карты не отдаются наружу

```bash
curl -s -o /dev/null -w "%{http_code}\n" \
  "http://localhost:5092/assets/$(ls -S excalidraw-app/build/assets/*.js | head -1 | xargs basename).map"
```

Ожидается `404`. И в devtools на вкладке Sources теперь только
минифицированный код — исходников нет.

На этом обычно останавливаются. Не останавливайся.

### 3. Найди то, что проверка пропустила

В прошлой лабе `find` показал, что две карты в сборке **остались**. Посмотри,
что это за файлы, и попробуй достать их по HTTP:

```bash
find excalidraw-app/build -name "*.map"
curl -s -o /dev/null -w "sw.js.map: %{http_code}\n" http://localhost:5092/sw.js.map
```

Получишь `200`. Карты сервис-воркера отдаются наружу.

**Почему так.** `vite-plugin-pwa` генерирует `sw.js` и `workbox-*.js` уже
**после** того, как отработал плагин Sentry. К моменту удаления этих файлов
ещё не существует, под `filesToDeleteAfterUpload` они не попадают, и в Sentry
их карты тоже не уезжают.

Содержимое там не такое ценное, как исходники приложения — сгенерированный
код воркера и список файлов прекеша. Но урок важнее содержимого: **проверять
надо все `.map`, а не тот один, о котором подумал.**

### 4. Закрой утечку

Самый чистый способ — не генерировать эти карты вовсе. У `VitePWA` есть
секция `workbox`, и в ней — свой флаг для карт.

<details>
<summary>Эталон</summary>

`excalidraw-app/vite.config.mts`, внутри `VitePWA({ ... })` → `workbox`:

```ts
        workbox: {
          // не генерировать карты сервис-воркера: они создаются уже после
          // плагина Sentry и потому не попадают под filesToDeleteAfterUpload
          sourcemap: false,
          // don't precache fonts, locales and separate chunks
          globIgnores: [
```

</details>

### 5. Проверь ещё раз

```bash
yarn workspace excalidraw-app build:artifact
find excalidraw-app/build -name "*.map" | wc -l
```

Теперь должен быть **ноль**. Перезапусти стенд и убедись снаружи:

```bash
deploy/serve-stand.sh production-01 5092
```

```bash
curl -s -o /dev/null -w "sw.js.map: %{http_code}\n" http://localhost:5092/sw.js.map
```

`404`. Вот это и есть «карты закрыты».

## Разбор граблей

Если стектрейс всё ещё минифицированный, иди по списку сверху вниз.

| Что проверить | Как |
|---|---|
| Заливка вообще была | В логе сборки есть `Using environment variables configured...` и нет ERROR |
| Бандл и карты в Sentry есть | Settings → Projects → excalidraw-lab → Source Maps |
| Событие из правильной сборки | Пересоберите и повторите: событие от старой сборки имеет другой Debug ID |
| На одном стенде читаемо, на другом нет | Сравни имя файла в стектрейсе события с текущей сборкой (`ls excalidraw-app/build/assets/index-*.js`). Если имя другое, браузер выполнил старый бандл из кеша сервис-воркера: после обновления сборки первая загрузка идёт из кеша, и лишь через несколько секунд воркер перезагружает вкладку. Проверено: первая загрузка выполнила старый `index-*.js`, хотя сервер уже отдавал новый. Обнови страницу ещё раз или удали воркер: DevTools → Application → Service Workers → Unregister |
| Проект тот же | Слаг в `sentryVitePlugin` совпадает с проектом, куда летят события |
| Карты не удалены до заливки | `filesToDeleteAfterUpload` — не путать с ручным `rm` в скрипте сборки |
| Sentry успел обработать | Расшифровка не мгновенная; подожди минуту и обнови событие |

Чего в этом списке **нет** — так это совпадения релизов. При Debug ID оно ни
на что не влияет (лаба 03).
