# Как `render-config.sh` собирает `config.js`

Разбор скрипта `deploy/render-config.sh` из лабы 02b. Все выводы ниже —
настоящие: команды прогнаны на `deploy/stands/staging-01.json` с `jq` 1.7.1.

## Скрипт целиком

```bash
set -euo pipefail

config_url="${1:?укажи URL конфигурации стенда}"
target_dir="${2:?укажи каталог со сборкой}"

raw="$(curl -fsS "$config_url")"

mkdir -p "$target_dir/config"
jq '.app' <<<"$raw" >"$target_dir/config/app.json"

jq -r '"window.__APP_CONFIG__ = " + ({environment, stand, sentry} | tojson) + ";"' \
  <<<"$raw" >"$target_dir/config.js"
```

## Обвязка

**`set -euo pipefail`** — скрипт останавливается на первой ошибке (`-e`), на
обращении к незаданной переменной (`-u`) и на ошибке в любом звене конвейера,
а не только в последнем (`pipefail`). Для entrypoint это важно: пусть лучше
контейнер не стартует, чем стенд поднимется с пустой или битой конфигурацией.

**`${1:?сообщение}`** — взять первый аргумент, а если его нет, завершиться с
этим сообщением.

**`curl -fsS`**

- `-f` — при HTTP-ошибке (404, 500) завершиться с ненулевым кодом. Без него
  `curl` молча сохранит HTML страницы ошибки, и дальше `jq` будет разбирать
  её вместо конфигурации;
- `-s` — не показывать индикатор загрузки;
- `-S` — но сообщение об ошибке всё-таки вывести.

`curl` понимает и `http://`, и `file://`, поэтому один и тот же скрипт
работает и с внутренним сервисом конфигурации, и с `deploy/stands/*.json`.

**`<<<"$raw"`** — here-string в bash: передаёт содержимое переменной в stdin
команды. Кавычки сохраняют переводы строк. Конфигурация скачивается один раз и
разбирается двумя вызовами `jq`, без повторного запроса.

## Команда для `config.js`

```bash
jq -r '"window.__APP_CONFIG__ = " + ({environment, stand, sentry} | tojson) + ";"'
```

Фильтр в одинарных кавычках, чтобы bash не трогал `"` и `$` внутри.

| Кусок | Что делает |
|---|---|
| `-r` | печатать строку как есть. По умолчанию `jq` выводит JSON, и строка печаталась бы в кавычках и с экранированием |
| `"window.__APP_CONFIG__ = "` | строковый литерал |
| `+` | для строк — склейка |
| `{environment, stand, sentry}` | новый объект из трёх полей входа. Сокращение для `{environment: .environment, stand: .stand, sentry: .sentry}` |
| `\| tojson` | сериализовать объект в однострочную JSON-строку |
| `( … )` | скобки нужны из-за приоритета операторов, см. ниже |
| `+ ";"` | точка с запятой в конце |

Результат:

```js
window.__APP_CONFIG__ = {"environment":"staging","stand":"staging-01","sentry":{"tracesSampleRate":1.0}};
```

Это валидный JavaScript — файл загружается в `node` и даёт объект:

```
{ environment: 'staging', stand: 'staging-01', sentry: { tracesSampleRate: 1 } }
```

## Что будет, если убрать деталь

**Без `-r`** — на выходе строковый литерал, а не присваивание.
`window.__APP_CONFIG__` так и останется неопределённым:

```
"window.__APP_CONFIG__ = {\"environment\":\"staging\",\"stand\":\"staging-01\",\"sentry\":{\"tracesSampleRate\":1.0}};"
```

**Без `tojson`** — строку и объект сложить нельзя:

```
jq: error (at <stdin>:12): string ("window.__A...) and object ({"environme...) cannot be added
```

**Без скобок** — та же ошибка. У `|` в `jq` самый низкий приоритет, ниже, чем у
`+`, поэтому

```
"…" + {environment, stand, sentry} | tojson + ";"
```

разбирается как

```
("…" + {environment, stand, sentry}) | (tojson + ";")
```

и сложение строки с объектом выполняется раньше сериализации.

## Почему только три поля, а не весь конфиг

`{environment, stand, sentry}` — белый список. `config.js` публичный: его
может скачать любой, кто открыл страницу. Туда попадает только то, что нужно
до старта приложения. Секция `app` и всё, что потом добавят в сервис
конфигурации — например, внутренние адреса, — наружу через этот файл не уедет.

Если какого-то поля во входе нет, `jq` подставит `null`, а не упадёт. В
`sentry.ts` это покрыто: `??` одинаково обрабатывает и `null`, и `undefined`.

## Почему `jq`, а не шаблон через `echo`, `sed` или `envsubst`

`tojson` экранирует кавычки, обратные слэши и управляющие символы. Значение с
кавычкой остаётся корректным JavaScript:

```js
window.__APP_CONFIG__ = {"environment":"stag\"ing</script>","stand":"x","sentry":{}};
```

Подстановка строки в шаблон ломается на первой же кавычке:

```bash
env_value='stag"ing'
echo "window.__APP_CONFIG__ = {\"environment\":\"$env_value\"};"
```

```js
window.__APP_CONFIG__ = {"environment":"stag"ing"};   // SyntaxError
```

Если значения хоть как-то зависят от внешнего ввода, такая подстановка — ещё
и возможность внедрить в страницу чужой код.

Заодно видно, почему `config.js` лучше держать отдельным файлом, а не
встраивать в `index.html`: последовательность `</script>` в значении внутри
встроенного `<script>` закрыла бы тег. `tojson` символ `/` не экранирует.

## Команда для `config/app.json`

```bash
jq '.app' <<<"$raw" >"$target_dir/config/app.json"
```

Берётся секция `app` и печатается как JSON с отступами. `-r` здесь не нужен:
результат должен остаться JSON. Так выглядят файлы, которые приложение
запрашивает после старта.

## Если конфигурация уже лежит в файле

`jq` принимает путь к файлу аргументом, here-string не нужен:

```bash
jq -r '"window.__APP_CONFIG__ = " + ({environment, stand, sentry} | tojson) + ";"' \
  /tmp/stand-config.json > /usr/share/nginx/html/config.js
```
