# Практикум: Sentry в React-приложении

Настройка Sentry «как в рабочем проекте» на базе реального open-source
приложения — [Excalidraw](https://github.com/excalidraw/excalidraw)
(Vite 5 + React 19 + TypeScript, монорепо на yarn workspaces).

## Что будет в конце

- Артефакт собирается **один раз** и без изменений раскатывается на любые
  стенды. Окружение сообщает сам стенд, а не сборка.
- Ошибки в Sentry разложены по окружениям (`staging`, `production`) и помечены
  конкретным стендом.
- Source maps **не отдаются наружу**: `curl` по `.map` возвращает 404, в
  devtools лежит минифицированный код.
- При этом стектрейс в Sentry читаемый на всех стендах сразу — после одной
  заливки при сборке.
- Auth-токен заливки живёт только в GitHub Secrets. На ноутбуке его нет.
- Шум отфильтрован, чувствительные данные не уезжают.
- GitHub Actions собирает артефакт, раскатывает его на staging, после
  подтверждения — на прод, и регистрирует каждую выкатку в Sentry.

## Чем это отличается от туториала из документации

Sentry в Excalidraw **уже настроен** — частично и с решениями, которые в твоём
проекте не годятся. Ты не заполняешь пустое место, а доводишь чужую рабочую
конфигурацию до продакшн-уровня. По дороге встретятся настоящие вещи, которых
не бывает в туториалах: чужой error boundary, который проглатывает ошибки
рендера; ключ шифрования в URL, который нельзя отправлять в Sentry; и
исходники, которые прямо сейчас лежат в открытом доступе.
